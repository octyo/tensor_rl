### 1. Launching an Experiment (`sim/train.py`)
Your main entry point for running any test will be the `sim/train.py` script. You won't need to hardcode changes every time you want to test a different setup; instead, you'll use command-line arguments. 

For example, to run a baseline standard Neural Network on a Minigrid environment, you would run:
`python sim/train.py --env MiniGrid-Empty-5x5-v0 --network standard --episodes 1000`

To run the same environment but using a Tensor Train (TT) decomposed network with a rank of 4, you would simply change the command:
`python sim/train.py --env MiniGrid-Empty-5x5-v0 --network tt --rank 4 --episodes 1000`

### 2. What Happens Under the Hood (Initialization phase)
When you press enter, `sim/train.py` acts as the conductor:
1. It calls `sim/envs/env_utils.py` to instantiate your specific Minigrid or Gymnasium environment and flatten the observation space so it's ready for linear layers.
2. It looks at your `--network` argument and calls `sim/models/q_networks.py`. If you requested a tensor decomposition (like `tt`), this network builder will pull the custom layers from `sim/models/tensor_layers.py`.
3. It initializes the core RL agent from `sim/agents/dqn_agent.py`, handing it the chosen environment and the constructed neural network.

### 3. The Training Loop & Data Collection (`sim/utils/logging_utils.py`)
As the DQN agent starts playing the game and training, the utilities in `sim/utils/logging_utils.py` kick in automatically:
* **Live Monitoring:** It calculates the "bitsize" (number of parameters/bytes of the chosen model) and streams this alongside the agent's reward, loss, and training speed to your online Weights & Biases (W&B) dashboard.
* **Local Auto-Saving:** Simultaneously, it saves these exact same metrics iteratively into a local CSV or JSON file inside a `sim/logs/` or `sim/data/` folder, clearly naming the file based on the parameters (e.g., `results_tt_rank4_minigrid_timestamp.json`).

### 4. Post-Training Statistical Analysis (`sim/analysis/stats.py`)
Once you've run your bash scripts or terminal commands overnight and gathered all your baseline and tensorized runs, you move to the analysis phase. 
* You will run `python sim/analysis/stats.py`.
* This script will loop through all the local CSV/JSON files generated in step 3.
* It will extract the steady-state rewards, convergence speeds, and bitsize metrics.
* It will compute statistical significance (like t-tests measuring if the CP-DQN actually trained significantly slower/faster than the standard DQN) and output final visual plots (matplotlib/seaborn) that you copy-paste directly into your bachelor thesis report.
